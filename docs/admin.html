GitHub connection

Requests

What phones have asked for. Answer with a tap: the phone is told the answer within a few minutes.

Phones without a name

Each phone asks for the person's name when it's first opened. These don't have one yet: type it here.

Lists

The public list is the general one. Make more lists for individual phones or groups, then choose which lists each phone uses under Phones.

Sites

Untick Home page for sites only needed in the background, like sign-in pages. Untick Include subdomains to allow only that exact site: google.com then won't open mail.google.com or maps.google.com. Its www. version always works. Fill in Only these pages to allow just those pages (and the pages below them) instead of the whole site. Tick No photos or videos to open the site without pictures and videos.

Bulk import from a spreadsheet

Columns in this order: domain, name, home page (yes or no), tile opens, subdomains (yes or no), only these pages (separated by spaces), no photos or videos (yes or no). Only the domain is required, and a header row is optional. Select the cells in Excel, Google Sheets or Numbers, copy them and paste here, or choose a file.

Download a template to fill in. Imported sites appear above as cards. Check them, then tap Save list.

Always blocked

Optional. Parts of allowed sites to keep blocked, one per line: a site like maps.google.com, or a single page like en.wikipedia.org/wiki/Fortnite.

Temporary access

Open something for a while only, even if it's otherwise blocked. Time runs out by itself, and the phone shows how much is left. Expired entries are removed automatically each day.

Add temporary access

Then tap Save list. (To answer a phone's request, use Requests at the top instead, so the phone is told.)

No photos or videos on specific pages

Optional. For a whole site, tick No photos or videos on its card above. Use this for single pages of a site that's otherwise shown normally, one per line, e.g. en.wikipedia.org/wiki/Shark.

Settings

Phones

Each phone registers itself the first time the app opens (when requests are set up). Tick the lists each phone uses. A site opens if any of the phone's lists allows it, and is blocked if any of them blocks it.

Approved requests

Where a change goes when you reply approve to a phone's request. You can still say approve public on any single request.

A phone's own Approved requests go to setting overrides this.

Ad blocking

Drops ads and trackers that pages load from known ad domains, using the AdGuard DNS filter (updated weekly). It can't remove ads a site serves from its own servers, like YouTube's video ads.

A phone's own Ads setting overrides this.

When a new phone is set up

The lists it starts with, besides its own private list (every new phone gets one, named after the person). Untick them all to start new phones with only their own list, which is empty until you add sites or approve requests. The app also comes with a copy of the public list built in (for before it's first online) only if public is ticked here when the app is built.

Archived phones

Phones that haven't opened the app for a while, probably uninstalled or not being used. Their private lists are kept in docs/lists/archive/, not deleted. A phone that's used again comes back by itself. After a factory reset a phone gets a new ID: use Give to phone to hand it its old name and lists.
